# 관리자 접근 제어와 배포

## 무엇이 달라졌나

이전 mio_funnel은 `/admin?token=…`의 토큰을 서버의 ADMIN_TOKEN과 비교했다. 해시 형태나 추측하기 어려운 URL 자체가 보안의 본질은 아니며 **서버 검사**가 있었다는 점이 중요하다. 이번 목업의 기존 `internal=1`은 표시 옵션으로 인증이 아니었다.

이제 `/prototype-review`, `/review`, `/tone-guide`는 요청마다 서버에서 세션을 검사한다. 내부 플래그·직접 URL·클라이언트 UI만으로 우회할 수 없다. `/api/admin/session`도 GET에서 세션을 검사한다. 홈과 약관은 공개 상태다. 공개 JS 번들에 목업 대사가 포함되는 것은 별개이며, 코드 자체는 공개 GitHub 저장소에 있다. 인증은 코드를 비밀로 만드는 기능이 아니다.

## 로컬 설정

```sh
node scripts/create-admin-env.mjs
npm run dev -- --webpack -p 3100
```

설정 스크립트는 `.env.local`을 owner-only(0600) 권한으로 생성하며 기존 파일이 있으면 덮어쓰지 않고 실패한다. `.env.local`은 Git에서 제외한다. 이미 설정된 컴퓨터에서는 스크립트를 다시 실행하지 않는다.

관리자 로그인: `http://localhost:3100/admin/login`

`.env.local`의 **MIO_ADMIN_ACCESS_KEY** 값을 로그인 폼에 입력한다. URL·이슈·PR·공유 채팅에 키를 넣지 않는다. **MIO_ADMIN_SESSION_SECRET**은 로그인 폼에 입력하지 않는 서버 서명 키다. 둘은 서로 다른 최소 32자 비밀값이며 생성기는 각각 32바이트 난수를 64자리 hex로 만든다. 키를 재사용하지 않는다.

## 배포 변경: Node 서버가 필요함

기존 `output: 'export'`를 제거했다. 정적 파일만으로는 서버 인증을 구현할 수 없다.

```sh
npm ci
npm run build -- --webpack
npm run start -- -p 3100
```

Vercel 등 Next.js 서버 런타임 또는 Node 서버에서 실행한다. 과거 `out/` 산출물은 새 서버 인증을 포함하지 않으므로 배포하지 않는다. 기존 CDN에 정적 관리자 파일이 배포되어 있다면 폐기·캐시 무효화가 별도로 필요하다. 이번 변경은 GitHub 게시이며 호스팅 설정이나 기존 배포 삭제를 자동 수행하지 않는다.

배포 환경에 아래를 별도로 설정한다.

- `MIO_ADMIN_ACCESS_KEY`: 로그인용 충분히 긴 난수
- `MIO_ADMIN_SESSION_SECRET`: 별도의 충분히 긴 난수
- `MIO_ADMIN_ORIGIN`: 외부 HTTPS origin과 정확히 일치(예: https://team.example.com), 경로·끝 슬래시 없음. 리버스 프록시의 내부 호스트와 다를 수 있으므로 운영에서 명시한다.

어느 키든 미설정·짧음·같은 값이면 로그인은 503으로 닫힌다. 기본 암호·우회 계정은 없다. `NEXT_PUBLIC_` 변수로 옮기지 않는다. 배포 시 강한 무작위 키를 써야 하며 문자열 길이 검사만으로 엔트로피가 보장되는 것은 아니다.

## 세션과 요청 보호

- 로그인은 same-origin JSON POST. URL 토큰을 받지 않음.
- 서버의 SHA-256 고정 길이 비교와 timingSafeEqual로 키 확인.
- HMAC-SHA256 서명, 4시간 고정 만료, 랜덤 nonce, 변조·만료 세션 거부.
- 쿠키: HttpOnly, SameSite=Strict, Path=/, 운영 Secure. 운영은 HTTPS 필요.
- 키 중 하나를 바꾸면 기존 세션 전체 무효화.
- 로그인 본문 1KB 제한. Origin 불일치·부재는 차단.
- 단일 프로세스 기준 전체 15분당 최대 10회 로그인 요청. 멀티 인스턴스·서버리스에서는 호스팅/WAF/공유 저장소 기반 제한을 **추가해야 함**. 전역 제한은 팀의 로그인도 잠시 막을 수 있음.
- 관리자 응답은 no-store, no-referrer, noindex, 프레임 차단. 클라이언트 대시보드는 세션 확인 실패 시 숨기고 60초마다·다시 보일 때 권한을 확인.
- 로그아웃은 same-origin DELETE로 브라우저 쿠키 삭제. 다른 기기나 복사된 토큰은 만료까지 유효할 수 있음. 유출 시 키 교체 필요.

개인 계정·MFA·역할별 권한·기기별 철회·서버 감사 로그는 이번 범위가 아니다. 고객 데이터가 중앙화되거나 팀 규모가 늘면 관리형 인증/SSO 및 운영 통제를 도입한다.

## 데이터 범위

지금 대시보드는 브라우저의 목업 이벤트·수동 집계·검토 기록만 다룬다. 서버 로그인은 다른 사람의 로컬 저장소를 지우거나 암호화하지 않는다. 같은 기기·프로필을 쓰는 사람은 개발자 도구 등으로 로컬 저장소에 접근할 수 있다. 원문·개인식별정보를 검토 메모나 가져올 파일에 넣지 말고 신뢰할 수 있는 팀 기기에서 사용한다.

실제 DB API를 만들 때에는 각 핸들러/데이터 접근 경계에서 인증·권한·데이터 최소화를 다시 검증한다. URL 난독화, 내부 메뉴 비노출, CORS만으로 API를 보호하지 않는다.

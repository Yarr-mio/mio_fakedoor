# 9월 23일 · Mio AI 상담사 수요 실험

## 현재 구현 범위

프런트만 구현. 시각 디자인 유지. 프로필 클릭 후 4개 대화 방식 선택 → 작은 질문 → 최대 10개 직접 입력 → 피드백. '뭐라고 말해야 할지도 모르겠어요'는 몸/마음 중 어디가 더 지쳤는지 작은 질문으로 시작합니다. 버튼 선택을 메시지로 만들지 않습니다. 응답은 선택한 방식에 따른 고정 예시이며 사용자 내용을 이해하지 않습니다. 언제든 종료 가능합니다.

## 이벤트 계약

모든 이벤트: version=entry-v4, mode=scripted_demo, visitorId(동일 브라우저 localStorage), sessionId(현재 페이지 로드), conversationId(대화 방식 선택마다 생성), at(ISO), 현재 UTM 및 internal.

| 이벤트 | 발생 시점 |
| --- | --- |
| counsel_exposed | 랜딩 첫 마운트, 동일 마운트 중복 방지 |
| counselor_profile_click | 프로필 이미지 또는 마음 나누기 클릭 |
| conversation_start | 4개 대화 방식 중 하나 선택, 자기 이야기 작성 전 |
| first_message_sent | 해당 대화에서 처음 직접 작성한 비어 있지 않은 메시지를 보낼 때 |
| message_sent | 직접 작성한 메시지마다; 원문 없이 turn, length |
| 3_turn_reached | 해당 대화의 세 번째 직접 입력 |
| 10_turn_reached | 해당 대화의 열 번째 직접 입력 |
| conversation_restart | 이전에 메시지를 쓴 대화와 다른 대화에서 첫 메시지를 실제로 보낼 때 |
| feedback_submitted | 체험 후 평가·선택적 상황/이유/대체재/직접 남긴 의견 제출 |

프로필을 보고 나간 방문, 방식만 선택한 방문, 직접 입력한 방문을 구분합니다. first_message_sent는 직접 작성한 메시지이지, 내용의 유의미함이나 진짜 자기 공개를 판정한 이벤트가 아닙니다. 인사도 포함되므로 정성과 함께 해석합니다.

재대화는 same_visit / later_visit로 나누고 직전 메시지부터 elapsed_hours를 기록합니다. 새로고침도 later_visit이므로 이것만으로 실제 재방문을 주장하지 않습니다. D1/D3 계산은 아직 없으며 사용자의 같은 날 즉시 재시작과 시간차 방문을 구분해서 리뷰해야 합니다.

## KPI

1. 노출 → 첫 메시지: 노출 기록이 있는 익명 브라우저 중 first_message_sent를 발생시킨 브라우저 비율.
2. 첫 메시지 → 3턴: 위 대상의 첫 메시지가 있는 conversationId 중 같은 ID로 3_turn_reached를 발생시킨 비율.

숫자에는 분자/분모를 함께 표시. 0 분모는 —. 프로필 클릭률을 성공 KPI로 사용하지 않습니다. 재방문 대화는 두 번째 지표의 별도 대화로 포함됩니다. visitorId는 사람 수가 아니며 기기·브라우저 변경 시 다른 ID입니다.

`/review`에서 내부 트래픽(?internal=1)을 기본 제외하고 JSON 내보내기에도 같은 필터를 적용합니다. 이 플래그는 현재 URL 기준입니다. 팀은 매번 ?internal=1로 진입하세요. 유입 UTM은 매 이벤트의 현재 URL 기준이며 장기 first-touch attribution이 아닙니다.

## 정성

편안함 / 비언어 표현 영향 / 향후 실제 AI 이용 의향 + 선택적 유입 이유, 상황, 기존 대체재, 다시 찾거나 찾지 않을 이유. 자유 의견은 사용자가 별도로 작성해 제출한 피드백이며 상담 대화 원문은 저장하지 않습니다. 피드백 입력 아래 브라우저 보관 안내를 표시합니다.

GO: 반복적 자기 이야기와 사람/기존 대체재 대비 구체적인 선택 이유, 일부 실제 이후 방문의 재대화.
ITERATE: 클릭→입력이 약하면 진입 장벽, 대화→재사용이 약하면 대화 가치 점검.
KILL/PIVOT: 적합한 대상에게 충분히 노출했는데 관심·대화가 약하고 호기심/기존 대체재 선호가 반복됨.

실제 캠페인에서는 대상 적합성, 채널, 관찰 기간, 표본 수와 누락을 함께 검토합니다. 이 프로토타입의 예시 대화 기록만으로 GO를 결정하지 않습니다. 인터뷰 인용은 실제로 수집한 것만 넣고, 데모 데이터와 섞지 않습니다.

## 저장 및 후속 연결

localStorage: mio_counsel_events_v4 (최근 2,000개), mio_counsel_visitor_v4, mio_counsel_last_message_v4. 이전 UI 버전과 분리. 이벤트가 오래되어 잘리거나 저장소가 차단되면 기록 누락 가능. /review는 전체 사용자 집계가 아니라 현재 브라우저에서 남은 기록의 합계입니다.

실제 트래픽으로 대화 효용·재사용을 검증하려면 별도로 승인된 실제 AI 응답과 중앙 이벤트 수집 연결이 필요합니다. 현재 코드는 네트워크 요청 없이 계측 계약·UI 흐름만 검증합니다. 이번 변경에는 리포트/CBT/Todo를 추가하지 않았습니다.

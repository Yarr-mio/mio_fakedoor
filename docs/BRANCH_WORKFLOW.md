# 브랜치와 인수인계

현재 인수인계 브랜치는 `codex/fakedoor-need-flow`, PR 대상은 `main`이다. 기본 브랜치를 직접 갱신하지 않고 초안 PR에서 화면·대사·연동 범위를 함께 검토한다. 별도 장기 `develop` 브랜치는 두지 않는다.

1. 이번 초안 PR에서 FE·BE가 README와 대화 정책을 확인하고 로컬 실행으로 기대 동작을 공유한다.
2. 검토가 끝나면 PR을 리뷰 가능 상태로 전환하고 검증 후 main에 병합한다. 이번 게시 작업은 병합이나 배포를 포함하지 않는다.
3. 이후 최신 main에서 작은 작업 브랜치를 만든다. 예: `codex/fe-chat-api`, `codex/be-consent`, `codex/be-llm-dialogue`.
4. 이번 PR 병합 전에 병행 작업이 필요하면 인수인계 브랜치에서 분기하고 PR 대상도 인수인계 브랜치로 둔다. 기반 PR 병합 후 대상과 차이를 다시 확인한다.
5. PR마다 변경한 동작, API 계약 변경, 검증 결과와 남은 작업을 적는다. 공유 브랜치의 강제 푸시는 피한다.

브랜치 보호 규칙과 자동 배포 설정은 이번 작업에서 변경하지 않는다. 위 절차는 팀 운영 기준이며 GitHub에서 강제 설정된 정책을 뜻하지 않는다.

담당 역할과 시작 문서는 [README](../README.md)를 따른다. 연구 근거 문서의 `../../research/…` 링크와 검증 이미지의 `../output/…` 경로는 기존 로컬 Mio 작업공간 기준이며 이 프런트 저장소에는 포함되지 않는다. 상세 연구 자료는 별도로 공유된 근거 저장소/작업공간에서 확인한다.

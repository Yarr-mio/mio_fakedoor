# Mio 대시보드: 무엇을 보고 어떻게 결정하는가

## 현재 범위

`/prototype-review`는 관리자 로그인 후 보는 근거 검토 화면이다. 현재 자동 판정은 **PMF 판단 보류**다. 목업 이벤트로 실제 AI의 가치나 PMF를 판정하지 않는다. 중앙 데이터 수집은 구현하지 않았으며, 로컬 v5.2 기록 또는 담당자가 가져온 JSON을 브라우저에서 계산한다. 화면의 파일 가져오기는 서버 업로드가 아니다.

기존 이벤트 키와 고객용 화면·대사·연구 코퍼스는 유지했다. 관리자 인증만 서버에서 처리한다. 변경된 배포 방식과 키 관리는 [ADMIN_SECURITY.md](ADMIN_SECURITY.md)를 따른다.

## 회의에서 읽는 순서

1. **분석 범위:** 목업/실사용, 대상 적합성, 기간, 유입 채널, 팀 트래픽, 원본 누락을 확인한다. 현 목업은 채널·안정적인 사용자 ID가 없으므로 세그먼트 수요나 사람 수로 해석하지 않는다.
2. **진입 과정:** 같은 방문에서 홈→시작→동의 화면 통과→대화 화면 진입 순서가 성립하는지 본다. 막힌 단계는 인터뷰와 함께 읽는다. 지원 정보 직행은 별도 성공 경로일 수 있다.
3. **가치 경험:** 실제 사용 관찰에서 도움, 부분적 도움, 도움 없음, 불편을 같은 비중으로 본다. 지금 수집하는 편의 피드백은 화면 이동에 대한 평가다.
4. **반복 사용:** 안정적인 가명 사용자 ID, 핵심 행동과 관찰 기간을 정한 뒤 성숙한 코호트를 본다. 재사용 의향은 실제 재사용과 다르다.
5. **판단과 다음 행동:** 추가 검증 / 병목 수정 / 가설 수정 / 판단 보류를 선택하고 반례와 부족한 근거를 기록한다. 부정적 응답이나 부재를 없애서 성공률을 높이지 않는다.

## 체험 지표 정의

| 지표 | 집계 | 해석 한계 |
|---|---|---|
| 방문 ID | 선택 기간의 고유 journeyId | 새로고침 시 변경. 사람·DAU 아님 |
| 연결 퍼널 | 동일 journeyId의 시간 순서상 홈→시작→동의→대화 진입 | 기간 안의 이벤트만 연결. 기간 경계·2,000개 상한으로 앞 단계가 없을 수 있음 |
| 단계 전환율 | 현재 연결 단계 수 / 직전 연결 단계 수 | 분모 0은 —. 첫 단계는 기준 100% |
| 직접 입력 | 대화 진입 이후 mock_input_sent 발생 방문 | 내용 수집 없음. 실제 자기노출·유의미 대화 판정 불가 |
| 예시 전송 | 대화 진입 이후 mock_fixture_sent 발생 방문 | 창작 문장 선택. 직접 입력과 중복 가능 |
| 필요·편의·후속 선택 | 항목별 방문의 마지막 응답 | 미응답자 제외, 자발적 응답 편향. 필요는 최초 획득 세그먼트가 아님 |
| 인터뷰 문의 | mailto 링크를 연 방문 | 전송·신청 완료가 아님 |
| 조용히 종료 | 해당 UI 종료 경로를 이용한 방문 | 원인·임상 악화·관측된 위해를 뜻하지 않음 |

날짜 필터는 Asia/Seoul 기준 시작일·종료일 포함이다. 이벤트 ID 중복을 제거하고 형식이 다른 행은 제외한다. JSON은 5MB/50,000개 이하이며 기존 자료를 대체한다. 임의 원문 필드는 버리고 필요한 메타데이터만 재구성한다. 가져온 파일의 진위·사용자 중복·채널 오염은 자동 검증하지 않는다. 로컬 저장이 차단되거나 손상되면 빈 기록으로 보일 수 있으므로 빈 표로 수요 0을 결론 내리지 않는다.

## PMF 근거 검토 규칙

5개 항목: 대상과 순간 / 실제 대화의 가치 / 반복 사용 / 유지와 이탈 / 자료 신뢰도.

각 항목에 방향(미확인·지지·혼합·반대), 유형(목업·인터뷰·실사용), 근거 ID·기간, 관찰·반례·한계를 남긴다. 원문·이름·연락처는 입력하지 않는다. 근거 ID는 팀이 원자료를 다시 찾을 수 있는 식별자다.

- 출처·관찰 기입 없는 평가는 판정에서 제외한다.
- 목업 자료는 실제 PMF 근거로 승격하지 않는다.
- 가치·반복·유지 항목은 실제 사용 관찰 유형일 때만 해당 판정에 반영한다. 인터뷰는 고객 가설을 보완하지만 관측 행동을 대신하지 않는다.
- 5개 항목 모두 실제 검토 조건을 갖춘 지지면 **가치 신호 · 추가 검증**을 제안한다. “PMF 달성”을 출력하지 않는다.
- 사용 가능한 항목에 반대 근거가 있으면 **가설 수정 검토**를 제안한다. PMF 부재의 확정이 아니다.
- 나머지는 **판단 보류**. 혼합·미확인을 점수 0으로 바꾸지 않는다.

이는 담당자 입력에 대한 검토 보조 규칙이다. 입력 유형의 진위, 표본의 충분성, 모집 편향, 인과성을 자동 확인하지 않는다. 5/5는 품질 점수나 성공률이 아닌 입력 조건 충족 수다. 검토 기록은 `mio_admin_evidence_v1`에 브라우저별로 저장하며 서버 공유·감사 로그가 아니다. 비밀을 입력하지 말고 공유 컴퓨터 사용 후 로그아웃한다.

## 실사용 코호트 가져오기

BE가 실제 사용자 기준으로 중복 제거한 **집계 결과**만 전달한다. 현 목업 이벤트에서 만들지 않는다. 이름·메일·사용자 ID·대화 원문은 필요하지 않다. 표에 표시된 수동 집계는 원자료 검증 완료를 뜻하지 않으며, 근거 검토 결과를 자동 갱신하지 않는다.

- 시간대: Asia/Seoul. 월요일 00:00~다음 월요일 00:00의 달력 주.
- 코호트: 첫 핵심 행동이 발생한 주에 가입한 것이 아니라, **첫 핵심 행동**으로 편입된 고유 사용자. size는 해당 코호트 전체 수.
- W0: 첫 핵심 행동 주. W1: 다음 달력 주. D7 또는 가입 후 7일 창과 다름.
- 핵심 행동을 해당 주에 한 번 이상 수행하면 retained 1명. 여러 번 수행해도 1명. 첫 행동 코호트는 W0=size.
- `asOf`는 해당 날짜 00:00 KST의 배타적 집계 마감 시각. 주가 끝나기 전에는 그 칸을 반드시 null로 둔다. 성숙했으나 자료가 없는 칸도 null로 둘 수 있다. 관측된 0만 0으로 기록한다.
- 반복 이벤트·기기·계정 중복은 BE가 해결한다. 팀 계정 제외를 확인한 뒤 teamExcluded=true로 전달한다.
- 기간별 합계는 관측된 코호트 분자 합 / 해당 코호트 size 합이다. 서로 다른 기간의 분모·코호트 구성이 달라질 수 있으므로 전체 곡선을 한 집단의 생존 곡선으로 오해하지 않는다.
- 1MB, 최대 104개 코호트, W0~W12를 지원한다. 월요일·중복 주·범위·미성숙 수치를 검사한다.

예시 값은 **형식 설명용**이며 실제 성과가 아니다. 화면의 양식 다운로드는 빈 코호트 배열을 제공한다.

```json
{
  "version": "mio-cohort-v1",
  "mode": "live_aggregate",
  "timezone": "Asia/Seoul",
  "asOf": "2026-09-14",
  "coreAction": "팀이 확정한 핵심 행동 v1",
  "sourceRef": "집계 실행 ID",
  "teamExcluded": true,
  "cohorts": [
    { "weekStart": "2026-08-31", "size": 10, "retained": [10, 2, null] }
  ]
}
```

## Carrying Capacity 적용

제공 자료: `1771523681207-toss-carryng-capacity.pdf`, 60쪽, 표지 “토스 리더가 말하는 PO가 꼭 알아야 할 핵심 개념 / 성장의 본질과 Carrying Capacity”, onlydecks 편집본. 외부 검증된 원자료와 동일하다고 주장하지 않는다. PDF 자체는 저장소에 복제하지 않았다.

반영한 개념:
- p.4·7: 유입/이탈 균형. 유입에 신규와 재활성을 구분해 포함할 수 있음.
- p.12~15: 활성 행동·이탈·집계 주기를 먼저 고정.
- p.21·24·29: 유료·자연 유입 분리, 유입·이탈이 변할 수 있다는 한계.
- p.32~34·44: 유지 곡선과 충분한 관찰 기간, 떠나는 이유와 남는 이유를 함께 검토.
- p.37~42·47~50: 아하 모먼트 후보를 정의하되 인과와 상관 구분.

화면 계산기는 아래 **상수 가정 모형**이다.

`N(t+1) = N(t) × (1 − c) + I`, `N* = I / c` (0 < c ≤ 1).

I는 기간당 신규+재활성 유입 수, c는 그 기간 기초 활성 집단의 이탈 비율, N은 동일하게 정의한 활성 규모다. 신규·재활성은 기초 집단과 겹치지 않게 한다. 5% 입력은 0.05로 계산한다. 기간당 모든 수치는 같은 단위여야 한다. 재활성화·채널·활성 정의가 달라지면 다른 모형으로 본다.

0% 이탈에서는 유일한 유한 균형을 출력하지 않는다. 음수·100% 초과·숫자 아님·오버플로 입력은 거부한다. 초기 입력은 비어 있으며 로컬 클릭 수를 유입·활성에 자동 대입하지 않는다. 12기간 추이는 가정값이며 사용자 수 예측 성과나 자동 PMF 판정이 아니다.

적용하지 않은 단정:
- 20/40/70% 잔존 = 사업 가치 등급, 80% CC = 보편 광고 임계치, 95% RPV = 모든 제품의 합격선.
- 짧은 관찰로 미래 MAU를 정확히 알 수 있다는 주장. 활성 규모를 정의 없이 MAU라고 바꾸지 않는다.
- SHAP나 행동군의 높은 잔존만으로 인과를 증명한다는 주장. 초기 행동과 미래 잔존을 분리하고 선택 편향·시간 누출을 검토한다.
- p.47 표의 RPV 표기·분모는 혼동 가능성이 있어 그대로 구현하지 않았다. 행동을 한 집단의 유지 확률을 보고 싶다면 그 집단의 유지자 / 그 집단 전체라는 분모부터 명시해야 한다.

특히 Mio는 어려움이 해소되거나 전문 도움으로 이동해 사용을 마칠 수 있다. 지속 방문 자체를 치료·도움의 목표로 강요하지 않는다. 낮은 잔존의 이유를 확인하고, 코호트의 `1−리텐션`을 기간 전체 활성 집단의 이탈률과 혼동하지 않는다.
